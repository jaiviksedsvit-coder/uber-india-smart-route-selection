## Why This Works for PM Interviews

1. **Honest & Credible:** Explicitly framed as a *Product Improvement Case Study* — PM hiring managers respect self-initiated teardowns.
2. **Full PM Lifecycle:** Demonstrates Problem Discovery → Quantitative Sizing → PRD Writing → Systems Architecture → Working Prototype.
3. **Hyperlinked Proof:** Links to a live, deployed prototype — not slides or a PDF.
4. **Two-Sided Marketplace Angle:** Addresses both rider experience *and* driver navigation alignment — signals systems-level PM thinking.

---

## Interview Defense Notes

If asked "What did you actually build?":
- **Rider-side:** Fully interactive web prototype (route toggle, dynamic pricing, vehicle selection, booking modal).
- **System Specification:** Authored complete PRD and technical architecture for the driver-side closed-loop waypoint injection protocol.
- **What you did NOT build:** Native Android driver app (requires access to Uber's proprietary driver APK).

If asked "Where do your numbers come from?":
- The case study does not cite speculative metrics in the resume bullet — all quantitative modeling is documented with methodology in the GitHub repo under `docs/02_strategy_and_market/Secondary_Research.md`.
